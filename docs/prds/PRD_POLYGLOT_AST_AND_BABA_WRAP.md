# 📄 PRD: Polyglot AST Engine & Canonical `baba wrap` (Harness² Remediation)

## 🎯 1. Executive Summary & Problem Statement

### 1.1 The Context-Rot & Superficial Remediation Dilemma
High-level harness audits (such as raw file presence checks or generic linter wrappers) provide a bird's-eye view of repository hygiene, but they fail to inspect the underlying AST (Abstract Syntax Tree) for subtle context-fencing hazards:
- **Unparameterized Dynamic Queries:** LLM code generators frequently introduce unparameterized SQL queries via string interpolation or concatenation (e.g. `f"SELECT * FROM users WHERE id = {user_id}"` or template strings), introducing critical security vulnerabilities.
- **Assertionless & Mock-Only Tests:** Fragile tests generated by AI agents often pass trivially by mocking everything while executing zero real behavioral assertions, giving a false sense of test coverage.
- **Hardcoded Credentials & Leaked Seams:** Secrets, dummy tokens, and boundary-leaking patterns bypass simple regexes while remaining structurally detectable inside the AST.
- **Missing Remediation Loop:** Developers and agent runners receive abstract scores without an actionable, deterministic blueprint (`DIAGNOSTIC.md`) detailing exactly what lines fail, why they violate context fencing, and how to surgically resolve them.

### 1.2 The Matryoshka Solution: `baba wrap`
Matryoshka Phase 4 introduces the **Polyglot AST Engine** and the canonical **`baba wrap`** (`matryoshka wrap`, `bbyg wrap`) command:
1. **Zero-Host-Dependency AST Engine:** Powered by portable WebAssembly (WASM) Tree-sitter parsers, executing natively inside Bun without requiring host C/C++ compilers, Python, or Rust toolchains.
2. **Contextual AST Antipattern Linter:** Evaluates code across TypeScript/JavaScript, Python, Go, and Rust for SQL injection patterns, assertionless tests, and hardcoded secrets.
3. **Harness² Composite Scoring:** Merges the foundational `harness-score` oracle with AST-level deductions into a weighted composite score (0–100).
4. **Actionable `DIAGNOSTIC.md` Output:** Deterministically compiles an anti-slop, human-and-agent-readable diagnostic report with exact line citations, AST node types, and surgical fix recommendations.

## 🛡️ 3. The 9 Production Dimensions Audit

| # | Dimension | Engineering Invariant |
|---|---|---|
| 1 | **Input Validation** | Validate all target paths against path traversal (`..`). Ignore binary files, vendor directories (`node_modules`, `.venv`, `target`, `vendor`), and files exceeding 500KB to prevent memory exhaustion. |
| 2 | **Failure Modes & Timeout** | AST parsing per file is bounded by a 2000ms timeout. Graceful degradation: if a grammar fails to parse a file, log a warning and continue without crashing the run. |
| 3 | **Idempotency & Retry** | Running `baba wrap` multiple times on unchanged source produces byte-for-byte identical `DIAGNOSTIC.md` and JSON output. Atomic file writes (`.tmp` -> rename). |
| 4 | **Authorization & Scopes** | Read-only inspection of source files. Writes only to designated report path (`DIAGNOSTIC.md` by default or custom `--output`). Zero credential leakage in reports. |
| 5 | **Concurrency & Locks** | Parallel file inspection using async workers bounded by `navigator.hardwareConcurrency` to maximize throughput without thread thrashing. |
| 6 | **Data Lifecycle & TTL** | Temporary WASM parser instances and AST tree allocations are immediately freed after file traversal. No lingering memory bloat. |
| 7 | **External Fallbacks** | If `harness-score` binary is missing from PATH, fallback to built-in structural heuristics without failing the overall command. If WASM grammar fails to load, fallback to regex-based heuristic scan for that specific language. |
| 8 | **State Transitions** | Execution flows through deterministic states: `INIT` -> `ORACLE_SCAN` -> `AST_INSPECT` -> `SCORE_COMPOSITION` -> `REPORT_GENERATION` -> `EXIT(0|1)`. Invalid transitions abort immediately. |
| 9 | **Observability & Metrics** | Structured telemetry output: emit elapsed scan time, total files scanned, total AST violations detected, and composite score. Ready for OTel and Prometheus scraping. |

## 🛠️ 4. CLI Ergonomics

### Commands & Aliases
```bash
baba wrap [target-dir] [flags]
matryoshka wrap [target-dir] [flags]
bbyg wrap [target-dir] [flags]
```

### Flags
* `--output <file>`: Custom report path (default: `./DIAGNOSTIC.md`).
* `--json`: Outputs purely structured JSON to stdout for machine consumption and CI automation.
* `--strict`: Exits with non-zero code (`1`) if the Harness² score is below `--threshold` or if critical AST violations (e.g. SQL injection) exist.
* `--threshold <number>`: Minimum acceptable Harness² score for strict mode (default: `80`).
* `--dry-run`: Performs all scans and prints the report to stdout without writing `DIAGNOSTIC.md` to disk.
* `--max-file-size <kb>`: Maximum file size to parse (default: `500`).

## 🧩 6. Subtasks Decomposition (Iterative BDD Delivery)

### 🔹 Subtask 1: Polyglot AST Walker & Tree-sitter WASM Engine
- Integrate WebAssembly-based Tree-sitter parser runtime.
- Support lightweight grammars for TypeScript/JavaScript, Python, and Go.
- Implement recursive file walker respecting `.gitignore`, max file size limits, and language mappings.

### 🔹 Subtask 2: Contextual AST Antipattern Rule Suite
- Implement `SqlInterpolationRule`: flags dynamic strings in database query expressions.
- Implement `AssertionlessTestRule`: flags test blocks lacking assertions or expectations.
- Implement `HardcodedCredentialRule`: flags high-entropy or cleartext API token variables.
- Provide node-level location metadata (file, line number, column, code snippet).

### 🔹 Subtask 3: Harness² Composite Scorer & Gap Aggregator
- Integrate with existing `harness-score` oracle wrapper (`src/core/oracle.ts`).
- Calculate weighted composite score: Score = (Oracle * 0.4) + (AST * 0.6).
- Compute deduction penalties based on rule severity (Critical: -15, High: -8, Medium: -4, Low: -2).

### 🔹 Subtask 4: `DIAGNOSTIC.md` & JSON Report Compilers
- Implement clean, deterministic Markdown compiler generating `DIAGNOSTIC.md`.
- Implement JSON serializer for programmatic consumption (`baba wrap --json`).
- Ensure output is 100% deterministic, free of AI buzzwords, and formatted for direct agent remediation.

### 🔹 Subtask 5: CLI Subcommand Integration, Guardrails & Strict Mode
- Wire `wrap` subcommand in `src/cli.ts` (replacing the placeholder).
- Support `--output`, `--json`, `--strict`, `--threshold`, and `--dry-run` flags.
- Implement atomic file writing and exit code 1 handling for CI gates under `--strict`.

## 📋 7. BDD Acceptance Criteria (Gherkin)

```gherkin
Feature: Polyglot AST Engine and Canonical baba wrap Command

  Scenario: Successfully detect unparameterized SQL query and generate DIAGNOSTIC.md

    And no "DIAGNOSTIC.md" should be created if "--dry-run" is also passed

    Given a project with a Harness² score of 72
    When the user runs "baba wrap --strict --threshold 80"
    Then the command should exit with code 1
```

## ⚡ 8. Performance & FinOps Guardrails
* **Execution Latency:** Complete full scan and report generation under **800ms** on repositories with <= 100 source files.
* **Memory Footprint:** Peak memory consumption under **120MB** RSS during full AST traversal.
* **Token Budget:** The generated `DIAGNOSTIC.md` MUST remain compact (< 1,500 tokens) to fit comfortably within the context window of any downstream remediating agent without crowding out code logic.
