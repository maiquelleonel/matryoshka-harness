# 📚 Matryoshka-Harness Experience Library (Harness² Meta-Learning)

Biblioteca canônica de lições arquiteturais, cicatrizes de segurança e governança agêntica acumuladas pelo projeto Matryoshka-Harness.

---

## 🛡️ Lições de Segurança & Isolamento Agêntico
- [security] OpenCode Console Breach & Distillation Attack: Em outubro de 2026, invasores comprometeram sistemas legados do OpenCode extraindo API keys privadas (Anthropic, OpenAI, Google) de 1.4% dos usuários para conduzir ataques massivos de destilação de modelos em labs externos (gerando faturas de 00 a .700 overnight). Lição: NUNCA persista API keys em texto claro na workspace; adote chaves efêmeras, mascaramento DLP e limites orçamentários rígidos.
- [security] CVE-2026-22812 & Unauthenticated Localhost RCE: Servidores HTTP de ferramentas agênticas ouvindo em localhost sem autenticação e com CORS frouxo permitem que páginas web maliciosas executem código no host do usuário. Lição: Ferramentas agênticas devem se comunicar exclusivamente via stdio (Model Context Protocol - MCP) ou sockets Unix fechados, dispensando portas TCP desnecessárias.
- [security] Airgap Zero-Egress Inegociável: Ferramentas de auto-harness devem assumir que o agente pode sofrer prompt injection ao ler dependências alienígenas. A cerca de execução deve operar com isolamento de kernel (--network none), bloqueando exfiltração de dados (C2 beaconing).

## 🧩 Convergência Universal de Plugins Agênticos
- [interoperability] Convergência de SKILL.md (Claude, Gemini, Codex, OpenCode): A indústria agêntica padronizou a especificação de Agent Skills em pastas isoladas com frontmatter YAML (skills/<nome>/SKILL.md). Um único repositório de skills pode ser consumido nativamente pelo Gemini CLI (gemini extensions install), Claude Code (claude --plugin-dir), OpenAI Codex e OpenCode sem duplicar regras de negócio.
- [interoperability] Dual Manifesto de Extensão: Para distribuição universal zero-install, o projeto mantém gemini-extension.json (para o Gemini CLI) e .claude-plugin/plugin.json (para o Claude Code) na raiz, permitindo instalação de 1 clique direto dos repositórios GitHub.
- [mcp] Model Context Protocol como Barramento de Ferramental: Em vez de bibliotecas pesadas instaladas localmente no host do cliente, o MCP via stdio é o padrão ouro para expor comandos de inspeção e remediação (mcp_matryoshka_scan, mcp_matryoshka_wrap).
- [mcp] Auto-Wiring Não-Destrutivo de MCP Servers: Ao injetar servidores MCP como codebase-memory-mcp nos clientes de agentes (.cursor/mcp.json, .gemini/settings.json, .claude/mcp.json), utilize merge profundo que preserve 100% dos campos de usuário existentes (temas, preferências, outros servidores MCP customizados). O suporte a --dry-run e --json assegura que pipelines e orquestradores possam simular e auditar planos de injeção sem tocar no disco.
- [mcp] Proteção contra Sobrescrita Destrutiva (Zero Destructive Overwrite): Em arquivos de configuração existentes (.cursor/mcp.json, .gemini/settings.json, .claude/mcp.json) que contenham JSON corrompido ou malformado, o auto-wiring NÃO deve sobrescrever o arquivo com objeto truncado. A falha deve ser isolada com status 'error' e erro explícito de parsing, evitando perda irreversível de configurações do usuário.
- [mcp] Idempotência Estrita sem I/O Redundante: Quando a configuração do codebase-memory-mcp já existir com comando e argumentos idênticos no arquivo de destino, o comando deve computar a ação como 'unchanged' e suprimir escritas em disco. Isso previne falhas de permissão em arquivos de configuração somente leitura (read-only / chmod 444) e impede alterações espúrias de mtime em ambientes monitorados por file watchers.
- [mcp] Isolamento Cirúrgico de Alvos MCP (--targets): Na injeção automática de servidores MCP, suportar filtragem seletiva de ambientes (--targets cursor,gemini,claude) permite que desenvolvedores configurem apenas os agentes utilizados em sua máquina local sem poluir o repositório com configurações de ferramentas ausentes. Erros de escrita (ex: permissões ou diretórios bloqueados) devem ser contidos no alvo afetado com status 'error' e mensagem explícita, sem mascarar falhas no código de saída do CLI.
- [telemetry] Dashboard-as-Code para Grafos de Conhecimento MCP: Versionar dashboards Grafana em formato declarativo JSON (dashboards/matryoshka-grafana.json) permite rastrear métricas críticas de agentes (taxa de invocação de search_graph, latência percentil P95/P99, proporção de erro em chamadas MCP, densidade de nós de AST e contagem de gaps de governança remediados) sem depender de provisionamento manual na UI. Garantir expressões Prometheus parametrizadas e alinhamento estrito no grid de 24 colunas viabiliza importação imediata em stacks Prometheus/Grafana de produção.

## 📐 Governança de Código & Anti-Slop Adaptativo
- [governance] Zero SOLID Forçado em Arquétipos Não-Compatíveis: Forçar princípios SOLID puros em bases procedurais (WordPress/Drupal/PHP legado) ou em componentes reativos (React/Vue/Next.js) gera código prolixo, alucinação de classes abstratas desnecessárias e inchaço de tokens. O AGENTS.md deve detectar o arquétipo real do projeto e priorizar DRY e YAGNI, aplicando SOLID apenas onde a arquitetura comportar (Go, Rust, NestJS, Spring).
- [ast] Polyglot AST Walker & Tree-sitter WASM Engine com Fallback Resiliente: Em ambientes efêmeros ou sandboxes de execução restrita (onde downloads de grammars WASM da internet são vetados por políticas estritas de segurança airgap zero-egress), o motor de AST poliglota deve prover uma camada heurística sintática de alta performance para TypeScript, JavaScript, Python, Go e Rust. O walker de arquivos deve filtrar rigorosamente diretórios vendor (`node_modules`, `.venv`, `target`, `vendor`, `.git`, `dist`, `build`, etc.), arquivos binários (detecção de byte nulo `\0` nos primeiros 8KB) e arquivos que excedam 500KB (`maxFileSizeKb`), isolando falhas e timeouts por arquivo (2000ms max) para garantir que arquivos malformados não interrompam o scan do repositório, garantindo saída determinística e ordenada alfabeticamente.
- [ast] AST de SQL & Detecção Estática de Fragilidades: O uso de parsers de AST de SQL (sqlparser-rs / node-sql-parser) permite auditar queries em código de backend sem necessidade de conexão ativa com o banco, capturando anti-patterns críticos (SELECT * em tabelas grandes, N+1 em loops de ORM, ausência de índices em WHERE/JOIN e risco de injection) antes do commit.
- [finops] Modularização em SKILLS.md por Especialidade: Em vez de um AGENTS.md monolítico de 500 linhas que sobrecarrega a janela de contexto, decomponha as instruções em skills especializadas (.gemini/skills/ ou .cursor/skills/): skill-backend.md, skill-frontend.md, skill-api.md e skill-security.md. Carregar apenas a skill necessária reduz o custo por turno em até 60%.
- [harness] Oráculo de Avaliação vs Remediação Ativa: Não reinvente a roda. Utilize o paladini/harness-score como o oráculo determinístico de maturidade (L0 a L4) e concentre o valor do Matryoshka na remediação automatizada (wrap), gerando tráfego e prestígio mútuo para o software livre.
- [oracle] Subprocess Spawning de Oráculo com Bun.spawn: Ao executar ferramentas oráculo externas (como paladini/harness-score) via Bun.spawn com stdout: "pipe", proc.stdout é exposto como ReadableStream. Em TypeScript estrito, utilize "instanceof ReadableStream" antes de consumir com "new Response(proc.stdout).text()" para evitar erros de tipo TS2345 sem violar guardrails de type assertion forçado.
- [fallback] Resiliência In-Memory de Oráculo Zero-Crash: Em ambientes onde ferramentas oráculo externas (como paladini/harness-score) não estão instaladas globalmente no PATH ou falham em subprocesso (timeout, erro de spawn ou saída não-JSON), o scanner deve acionar transparentemente um avaliador in-memory heurístico cobrindo integralmente os 5 eixos de governança (Contexto, Skills, Guardrails, Sensores, Higiene - 105 pts max). Isso assegura disponibilidade contínua do comando 'baba scan' sem exigir que o desenvolvedor instale binários globais ou dependências externas adicionais.
- [reconciliation] Conciliação Semântica Poliglota & Mapeamento de Gaps L0-L4: Ao conciliar os diagnósticos emitidos pelo oráculo (harness-score) com a base inspecionada, as ações de remediação devem se ancorar na realidade idiomática de cada linguagem (ex: pytest + FastAPI para Python, Pest/PHPUnit sem forçar SOLID para PHP WordPress, Bun test para TS). O mapeamento deve descobrir entidades reais (rotas, models, controllers) no layout do projeto e referenciá-las diretamente nas issues de remediação, evitando alucinações de padrões inexistentes.
- [agents] Gerador Adaptativo de AGENTS.md Ultraleve e Skills Modulares On-Demand: Ao estruturar diretrizes para agentes de IA (Issue #8 / SPEC-8), o arquivo raiz AGENTS.md deve ser estritamente ultraleve (< 200 tokens) para evitar context bloat e diluição de atenção. A especialização (Backend, Frontend, Database, Security, Testing) deve residir em .agents/skills/ com frontmatter YAML obrigatório (name e description), garantindo carregamento cirúrgico sob demanda pelos agentes e economizando mais de 85% de tokens por turno de inferência. A substituição com --force deve preservar o arquivo anterior como .bak, garantindo idempotência e segurança não-destrutiva.
- [skills] YAML Frontmatter Indexing & Carregamento On-Demand de Skills: Para mitigar inchaço de contexto e vazamento prematuro de diretrizes, as skills modulares em `.agents/skills/` exigem frontmatter YAML estrito (`name` e `description` com gatilhos de ativação explícitos). A indexação ocorre exclusivamente via metadados nos prompts iniciais (com economia superior a 70% de tokens), enquanto o corpo especializado é consumido apenas sob demanda por meio de funções isoladas (`loadSkillOnDemand`), mantendo isolamento estrito entre domínios arquiteturais (backend, frontend, database, security, testing).
- [profiler] Archetype Profiler & Seam Discovery Determinístico: A classificação de repositórios em arquétipos canônicos (api_backend, opinionated_monolith, reactive_frontend, systems_microservice, fullstack_hybrid) deve combinar inspeção de manifests poliglotas (com suporte a monorepos com subtrees apps/ e packages/) e descoberta de costuras arquiteturais reais (routes, models, controllers, services, views/templates, tests). Isso previne a injeção espúria de skills desnecessárias (como skill-frontend em APIs Django Ninja ou Rails API-mode) e garante adaptação cirúrgica de governança agêntica sem inchaço de tokens.
- [ast-rules] Suíte de Regras Contextuais de AST Antipatterns (SQL, Testes e Segredos): Ao auditar código gerado por IA para remediação agêntica, a análise puramente baseada em regex produz falsos positivos/negativos desastrosos. A suite de regras AST contextuais (`SqlInterpolationRule`, `AssertionlessTestRule`, `HardcodedCredentialRule`) opera sobre os nós e escopos estruturais dos arquivos parsed:
  1. `SqlInterpolationRule`: Detecta template literals e f-strings dinâmicas acopladas a comandos SQL (`SELECT`, `INSERT`, `UPDATE`, `DELETE`), bem como interpolações com `+` ou formatações dinâmicas (`fmt.Sprintf`, `%s`) passadas para APIs de banco de dados (`query`, `execute`, `Query`, `Exec`), fornecendo remediação precisa com queries parametrizadas.
  2. `AssertionlessTestRule`: Captura testes vazios ou sem asserções comportamentais (`expect`, `assert`, `t.Fatal`, etc.) em suítes de testes (`it`, `test`, `def test_*`, `func Test*`, `#[test] fn *`), evitando o falso verde (false green hazard) gerado por agentes que apenas invocam funções sem verificar o retorno.
  3. `HardcodedCredentialRule`: Identifica tokens com prefixos conhecidos (`sk_live_`, `ghp_`, `AKIA`, `AIza`, etc.) e variáveis com nomes sensíveis (`api_key`, `secret`, `token`, `password`) associadas a literais em texto claro de alta entropia de Shannon (H(S) > 3.0), ignorando leituras seguras de ambiente (`process.env`, `os.environ`, `os.Getenv`) e constantes de configuração benignas.
  A orquestração via `AstRuleSuite` provê agregação determinística com filtros por severidade (`minSeverity`) e desativação seletiva (`disabledRuleIds`), preparando o terreno para a composição do score Harness² e o relatório `DIAGNOSTIC.md`.
- [token-guard] Root AGENTS.md Template Engine & Token Guard Estrito: Para erradicar o inchaço de contexto e garantir economia contínua de FinOps, o motor de compilação de AGENTS.md opera com teto rígido inviolável (MAX_ROOT_AGENTS_TOKENS = 250, target < 200). Comandos detectados (test, build, lint) são sanitizados e normalizados contra quebras espúrias, e invariantes customizadas são acopladas sem ultrapassar o teto. O subcomando 'baba agents check [path]' valida a conformidade de tokens de arquivos existentes com paridade CLI total, retornando status binário e envelopes tipados (TokenGuardReport) para agentes e orquestradores.
- [compilers] Compiladores Context-Aware de Backend & Database Skills com Frontmatter YAML: Para combater alucinações e regras genéricas de IA (slop), as skills 'skill-backend.md' e 'skill-database.md' são compiladas dinamicamente via motores dedicados ('compileBackendSkill' e 'compileDatabaseSkill'). Os compiladores detectam automaticamente ORMs (Prisma, SQLAlchemy, Django ORM, Diesel, GORM, ActiveRecord, Eloquent) e engines de banco de dados (PostgreSQL, MySQL, SQLite) através de manifestos e dependências, injetando diretrizes especializadas (como 'include/select' no Prisma, 'selectinload' no SQLAlchemy, 'CREATE INDEX CONCURRENTLY' no Postgres e 'ALGORITHM=INPLACE' no MySQL) sem violar frontmatter YAML padronizado nem exceder o escopo de cada domínio.
- [compilers] Compiladores Context-Aware de Frontend & Security Skills com Frontmatter YAML: As diretrizes de frontend ('skill-frontend.md') e segurança ('skill-security.md') são compiladas contextualmente ('compileFrontendSkill' e 'compileSecuritySkill') identificando frameworks de interface (Next.js, React, Vue/Nuxt, Svelte, Astro, Angular), sistemas de estilização (Tailwind CSS) e mecanismos de autenticação/segurança (Next-Auth, JWT, Clerk, Supabase Auth, Django Allauth, Passport). O compilador injeta regras cirúrgicas para prevenção de Core Web Vitals/CLS ('next/image', dimensions), pure rendering, acessibilidade semântica (A11y), OWASP Top 10, sanitização estrita de input (prevenção de SQL injection, XSS, SSRF e Path Traversal) e zero secret leakage, preservando o frontmatter YAML estrito com chaveamento de escopo sem sobrecarregar a janela de contexto.
- [testing-compiler] Compilador Context-Aware de Testing & Verification Skill com Frontmatter YAML: O compilador 'skill-testing.md' ('compileTestingSkill') implementa formalmente The Seam Contract (Red-to-Green TDD discipline antes de alterar qualquer código de produção) e isolamento estrito de fixtures e mocks. Detecta dinamicamente test runners (Vitest, Jest, Pytest, Bun test, Cargo test, Go test, RSpec, Pest, PHPUnit) e frameworks E2E (Playwright, Cypress) a partir de manifests e arquivos de configuração, injetando diretrizes calibradas para matchers, fixtures com teardown isolado, locators semânticos de acessibilidade e mock boundaries no nível de borda (sem mocks espúrios da lógica de domínio interna). Preserva frontmatter YAML estrito com metadata indexável sob demanda e suporta regras customizadas de repositório.
- [cli-guardrails] CLI Subcommand & Overwrite Guardrails Não-Destrutivos: A geração de diretrizes agênticas (`baba agents generate [path]`) protege instruções customizadas preexistentes contra perda acidental de dados através de guardrails de sobrescrita. Sem a flag `--force` (`-f`), o comando falha imediatamente (código 1) caso `AGENTS.md` já exista. Com `--force`, o arquivo pré-existente é preservado deterministicamente em `AGENTS.md.bak` antes da reescrita, reportando `backupCreated: true` e `backupPath` no envelope JSON e no console. Em modo de simulação (`--dry-run`), nenhum arquivo é modificado em disco. O parser de linha de comando extrai argumentos posicionais isolando valores de flags com parâmetros (como `--max-tokens <num>`) para evitar que números sejam erroneamente interpretados como caminhos de projeto, garantindo paridade total entre os aliases `baba`, `bbyg` e `matryoshka`.

## ⚡ Portabilidade & Ergonomia de Terminal
- [tooling] Zero-Runtime Dependencies para o Usuário Final: Distribuir ferramentas CLI via Bun/Node (npx / bunx) garante que desenvolvedores de qualquer stack (PHP, Python, Ruby, Go) executem a cerca sem precisar de compiladores C/Rust ou runtimes adicionais no host.
- [ux] Naming Ergonomics (Baba / Baba-Yaga vs Matryoshka): Nomes complexos como 'matryoshka' sofrem com typos frequentes (matrioska, matrioshka). Fornecer atalhos de 4 letras no terminal como 'baba' (matriarca eslava) ou 'bbyg' (baba-yaga: remediação que parece bruxaria) maximiza a ergonomia sem perder a identidade visual do projeto.
- [cli] Aliases de Binários e Scripts no Package Manifest: Em ambientes de desenvolvimento com Bun, invocação via "bun run <alias>" requer mapeamento correspondente na seção "scripts" do package.json para permitir execução direta e paridade estrita nos testes de subprocesso (spawnSync).
- [cli] Dual Format Envelope for CLI Tooling & Agents: Ao expor resultados de auditoria agêntica via CLI, forneça simultaneamente saída visual rica em cores ANSI (via picocolors) para operadores humanos e envelope estruturado com duplo chaveamento camelCase/snake_case via flag '--json' (ex: remediationIssues e remediation_issues). Isso garante interoperabilidade plug-and-play tanto para ferramentas TypeScript tipadas quanto para pipelines de orquestração agêntica em Python.
- [sandbox] Permissões de Cache Bun em Ambientes Efêmeros: Em containers e sandboxes onde `/home/sandbox/.bun/install/cache` pertença ao `root`, configure `BUN_INSTALL_CACHE_DIR=/tmp/bun-cache` para evitar erros de permissão (`EACCES accessing temporary directory`) durante comandos `bun install`.
- [badge] Emissão Autônoma de Badges SVG Shields.io: Ao exportar selos visuais de governança agêntica (--badge), gere SVGs puros e autocontidos com dimensões calculadas, gradientes lineares, viewBox e tags semânticas de acessibilidade (role="img", aria-label e title), colorindo dinamicamente as réguas de maturidade (L0 vermelho #cf222e a L4 verde #2ea44f). O parser de argumentos do CLI deve diferenciar com segurança flags com parâmetros opcionais (--badge [path]) dos argumentos posicionais de diretório alvo, garantindo que subdiretórios pais inexistentes sejam criados recursivamente sem lançar ENOENT.
